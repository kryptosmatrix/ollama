Phase 5 — working down the unverified list, batch 1: the manager

Three of the twenty confirmed by probe, all in mcp/manager.go, all fixed.

D-2 — CALL AND CLOSE RACED ON A ServerState

Call took the *ServerState pointer under the read lock and then read Status and
Tools through it after releasing the lock, while Close wrote both fields in
place under the write lock. The race detector finds it immediately once a call
and a shutdown overlap:

    WARNING: DATA RACE
      manager.go:605  (Close writing)
      manager.go:565  (Call reading)

The whole suite had been passing under -race for the life of this branch. That
proved only that no test drove the interleaving. Call now copies what it needs
under the lock.

D-3 — A SWITCHED-OFF SERVER CAME BACK

Connect returns when its dials finish, but a dial it started can still be
running when the next Connect arrives, and the second cannot cancel the first.
The older attempt then installed its session and its state over the newer
decision. Probe output before the fix:

    CONFIRMED D-3: a disabled server came back as "connected"
    CONFIRMED D-3: a disabled server is offering 1 tools

This is the third member of one family. A disabled server that kept its process
was found and fixed during the build; a removed server that kept everything was
found by this review; this is the same shape again — an instruction from the
user losing a race with work already in flight. Each was found separately and
each was fixed in the branch it was found in, which is exactly how the first two
survived.

The fix is a per-server epoch rather than a fourth patch to a fourth branch.
Every attempt records the epoch it began in; anything that supersedes it —
closing a session, a later connect, a sign-in — moves the epoch on, and an
attempt whose epoch has moved declines to install its session, its release and
its state. That covers the branches nobody has thought of yet.

D-6 — A CLOSED MANAGER STILL CONNECTED

Connect set states and spawned goroutines that could only fail inside dial,
leaving a shut-down manager reporting a list of failures. It now returns.

A NOTE ON THE PROBE ITSELF. The first D-3 probe raced on its own shared
ServerSpec: the test wrote Disabled while the manager read it. That was the
test's defect, not the code's, and it was rewritten to use two configuration
objects as a reload from disk would produce. A probe that reports a race in its
own scaffolding proves nothing about the subject.
