Phase 5 — the last two: B-3 and D-4

Both confirmed and fixed. Three protections falsified.

B-3 — REVOCATION COULD GO TO A SERVER THAT NEVER ISSUED THE TOKEN

A protected resource may name several authorization servers. Revocation walked
that list and used the first one advertising a revocation endpoint, and the
stored record did not say which had issued the token.

The scenario that exposes it is narrower than "several servers": the issuing
server offers no revocation endpoint and a later one on the list does. The old
path then posted the refresh token to a server that had never issued it — and
RFC 7009 §2.2 has such a server answer 200 for a token it does not recognise,
because an unknown token already satisfies the request. So the user was told
they were signed out, the token stayed live at the server that issued it, and
the credential had additionally been handed to a third party.

SignInRecord now carries the issuer, learned at sign-in from the same metadata
lookup that decides the RFC 9207 issuer comparison, and kept across refreshes by
the same rule as ClientID: a refresh arriving without one must not erase it.
Both stores preserve it. Revocation asks that server and no other.

A record written before this carries no issuer, and the old list-walking
behaviour remains for exactly that case — its weakness named in the comment
beside it rather than left for someone to rediscover.

Being told the truth — that the token could not be revoked — is strictly better
than being told a comfortable lie, and that is what the test asserts.

D-4 — THE PREVIOUS SERVER WAS SHUT DOWN WHILE THE WRITE LOCK WAS HELD

Closing a session waits for the server process to exit. dial did that inside the
critical section, so replacing an unresponsive server would stall every Call,
States and Close for every *other* server until it died. closeSession has always
done this work outside the lock; this path had not. Both the session and the
release are now taken out under the lock and shut down after it.

Only the release half can be driven from a test — the transport seam controls
that function but not the protocol library's session — and both moved together,
so the release standing in for the session is the honest proof available. Said
here rather than implied.
