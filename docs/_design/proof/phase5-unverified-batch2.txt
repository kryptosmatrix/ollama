Phase 5 — working down the unverified list, batch 2

Five more settled. Four confirmed and fixed with a test that fails without the
change; one fixed defensively and recorded as such because it cannot be driven.

A1-4 — A LOOPBACK HOST WAS COMPARED CASE-SENSITIVELY

    CONFIRMED A1-4: url "http://Localhost:8080/mcp" must use https;
    plain http is allowed only for loopback addresses

Host names are case-insensitive (RFC 4343). Fixed with EqualFold; a real host
still has to use https, and the test asserts both halves.

E-4 — A DESCRIPTION AT THE DEPTH LIMIT WAS NEVER SANITISED

The depth-limit branch returned the server's raw text while the branch beside it
sanitised. It was the one place a careless or hostile server could put control
characters and unbounded length into a model's prompt.

E-7 — AN UNREADABLE TYPE WAS TREATED AS NO TYPE AT ALL

    {"name":"hosted__odd", ... "properties":{"n":{}}}

A "type" that is neither a string nor an array of strings was indistinguishable
from an absent one, so the model was told there was no constraint — the opposite
of the truth, since the server had said something Ollama could not read. It is
now recorded as a lost constraint and the model hears it.

B-4 — A TOKEN COULD BE POSTED OVER PLAIN HTTP

The protocol library validates the *scheme* of a revocation endpoint but leaves
it out of the https-or-loopback list it applies to the token, authorization,
registration and introspection endpoints. That was read in its source rather
than assumed, which is what the finding asked for. A revocation request carries
the refresh token in its body, so an authorization server naming an http
endpoint would have put a live credential on the wire in cleartext. Refused now,
loopback excepted.

C-4 — goString RETURNING EMPTY

Servers() now skips an item whose account cannot be read back rather than
appending an empty name that no caller can act on. There is no way to force
CFStringGetCString to fail from a test, so this carries no falsifier and is
recorded as defensive rather than counted — the same treatment as the PKCE
assertions and the slices.Clone.

TWO OF MY OWN TESTS DID NOT DISCRIMINATE, AND BOTH PASSED THE FIRST SABOTAGE

Recorded because it is the third time in this branch and the pattern is worth
naming.

  B2  The depth test nested a description twelve levels down. The depth-limit
      branch returns the schema it is handed at the moment the limit is
      crossed, and the intermediate objects had no description of their own, so
      the branch was never reached with anything to return. The test passed
      against the defect. It now carries a description at every level.

  B4  The endpoint test called requireSecureEndpoint directly. A predicate
      nothing consults is not a protection, and removing the call from
      revokeSignIn left the test passing. It now drives a real sign-out against
      an authorization server whose metadata advertises an http endpoint on a
      non-loopback host.

Both faults are the same one: asserting that a mechanism exists rather than that
the path uses it.
