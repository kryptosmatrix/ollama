Phase 5 repairs — the two structural defects from the cross-substrate review

Both were confirmed by probe before any fix; both now have a committed test
that fails without the change. Method as everywhere else: the protection was
broken in production code, the test observed to fail, and the file restored
byte-identical. Hashes before and after every attempt are in this file and
match.

D-1 — A SERVER REMOVED FROM THE CONFIGURATION KEPT RUNNING

Connect reconciled every server the configuration mentioned and never looked at
the ones the manager was already holding. forgetServersOutside now ends the
session, runs the transport's release, and deletes the state for every server
the configuration no longer names.

Deleting the state rather than marking it disabled is deliberate: a server that
is not configured has no status to report, and leaving one behind would put a
row in the app's list for something the user removed.

Two falsifiers, F3 and F4. F4 is the one worth having — it drops the state but
leaves the session, which is exactly the half-fix that would look right in the
interface while the subprocess kept running.

E-1 — TWO PROPERTIES SHARING ONE DEFINITION

The resolver's visited list lived on the resolver, one per tool, and was never
reset. The second sibling to reference a definition found it already there and
was reported as a cycle. The property was not dropped; it was emitted with no
type and no enum, and the note attached to the tool description told the model:

    - to: reference "#/$defs/currency" is cyclic

which is a false statement about the server's own schema. Correcting an earlier
description of this defect: it is not silent. It reaches the model as a
confident lie, which is worse.

The first repair made the chain local to one resolve call. That fixed siblings
and broke something else, and the pre-existing TestSchemaCyclicRefDegrades-
InsteadOfHanging caught it inside a minute: a definition containing a property
that refers back to itself closes its cycle through the *nesting*, not within
one chain of hops. With a purely local chain that case fell through to the
depth limit and the model was told the schema was "nested beyond the depth this
tool schema can express" — true, but a much less useful diagnosis than
"cyclic", and the test asserted the accurate one.

The chain is now threaded down the nesting path: siblings each extend the path
they share, and a self-referential definition is still caught and still named.
That is the shape that satisfies both cases rather than trading one for the
other, and the old test is what forced it.

NOT FALSIFIED, and kept anyway with the reason written beside it: the
slices.Clone in resolve. F1 replaced it with a plain append and the sibling test
still passed, because nothing in this package retains a chain long enough for
two siblings writing into one backing array to be observed. Sibling correctness
comes from threading the path, not from the copy. It is kept as a guard against
that changing and is recorded here as unfalsified rather than counted — the same
treatment given to the PKCE assertions in the flow record.
