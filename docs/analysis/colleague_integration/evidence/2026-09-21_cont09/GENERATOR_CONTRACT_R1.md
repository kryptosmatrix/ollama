## Source and design decision

`app/ui/ui.go:42` invokes tscriptify over responses/types.go. The module pins typescriptify-golang-structs v0.2.0; fresh execution reproduces gotypes.gen.ts byte-for-byte (SHA256 49052e66cbd7e279e7bc2abd0270df4f8746fb1545e0e8d486deb51cbf791154). The pinned generator hardcodes constructor/helper any, so configuration alone does not solve this. There are 35 classes and 16 conversion helpers. useChats.ts invokes generated constructors repeatedly; interfaces alone would remove runtime behaviour.

Proposed owning process: a small Node generation command runs the existing pinned Go generator into a fresh temporary file, applies an AST-checked annotation transform using the already installed TypeScript compiler, verifies identical emitted JavaScript under the project compiler options, and atomically replaces only the generated target after all checks succeed. The normal go:generate directive points to this command. No module-cache edits, new package/version, runtime helper, alternate model classes or hand edits of generated output.

Constructor inputs and conversion intermediates become unknown, not a renamed any. Assertions occur at the pre-existing unchecked materialisation boundary and are derived from each generated property's declared type. Public Go interface-valued JSON fields become a recursive JSONValue union (string, number, boolean, null, JSON arrays and objects). This describes serialized JSON; it is NOT a runtime validator and does not reject or repair malformed JavaScript inputs. No claim of input-validation safety is earned by this annotation repair. Existing Go producer behaviour, coercion, optional-field handling and error paths stay unchanged. In particular this work does not redesign time.Time conversion or the byte-array/raw-JSON wire contracts.

Strongest objection: an annotation adapter can drift from its upstream emitter or turn unsafe assertions into a false validation claim. Mitigations: version-pinned raw generator, reject unsupported AST/template shapes, compare emitted JavaScript before writing, retain the explicit unchecked-boundary statement, and executable regeneration/consumer tests. Copying the entire upstream generator to change its templates would add a maintained fork; replacing classes with interfaces breaks live consumers. Disabling lint or wrapping any in an alias is rejected.

## Requirements

G-01. Use the same Go source-model discovery and pinned generator, without a separately maintained list of model fields/classes. Running normal generation twice produces identical generated bytes; --check detects stale output without modifying it.
G-02. Retain all runtime class names, constructors, nested object/array/map conversion, Date transforms, primitive values, absent/null handling and malformed-JSON exceptions. Generated JavaScript must be byte-identical to raw upstream emission using the recorded project options. No new runtime code or imports in generated models.
G-03. Emit no explicit-any syntax. Typecheck all affected existing application consumers; lint has zero findings in the generated target and no new findings elsewhere. Remaining baseline debt is enumerated separately.
G-04. Generation failures, unsupported shapes, emission mismatch and --check drift leave the existing output unchanged and return a failing child exit. Never truncate the target before verification. Temporary material is scoped and regenerable; retain evidence under the existing task directory.
G-05. Default frontend tests cover real generated constructors, contrasting values, nested conversions and actual renderer consumption without replacing the generated classes or renderer. Dedicated generation tests cover the actual CLI and TypeScript annotation logic; keep ordinary frontend tests runnable without a Go installation. Required generation verification is an explicit candidate-acceptance command documented with the generator.
G-06. Freeze candidate and permanent tests in a local commit before T-05. Run clean–broken–clean controls in isolated copies: bypass annotation generation (lint must fail); drop nested conversion (consumer assertion must fail after compilation); corrupt a delivered value (contrasting-input assertion must fail after compilation). Show the fault reached its expected assertion. A missing dependency, collection failure or type error does not qualify as behavioural detection.
G-07. Capture all commands, full stdout/stderr, true exits, source/config/dependency identities and discovered/completed cases. Run the complete established frontend suite, project typecheck, full lint comparison and production frontend build. Independently reproduce required acceptance and controls with the selected DeepSeek judge before a passing bounded review.

## Scope and recovery

Expected owned changes: generator command/annotation module and tests; normal go:generate invocation; generated model output; required acceptance documentation. No production Go model/handler, store, renderer, dependency lock or lint-policy change is intended. An unexpected need to change runtime semantics returns to this contract before implementation.

The committed task branch and source baseline provide recovery for code; generated output is independently reproducible from retained Go source and pinned dependencies. Do not touch live conversations, Keychain, installations, global settings, other worktrees or unrelated processes. Main integration remains gated separately.
