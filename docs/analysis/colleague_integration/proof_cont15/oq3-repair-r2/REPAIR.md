## The six findings

**1. T8 could pass a reload wrongly committed while busy.** Built: T8 gains an ordinary turn after the held turn completes and before the idle reload, expecting revision 1 at generation 1 (`oq3_scenarios_test.go`, T8). A reload committed while busy shows there as revision 2 at generation 2; the idle reload that follows can no longer hide it as a no-op. The trial count is unchanged (the turn belongs to T8-X). Control: `TestOQ3ScorerControls` §5 runs T8's steps against a modelled adapter that commits the refused reload while its held turn keeps the selection it copied: 1 of 5 deliveries bad under this ledger, 0 of 4 under the round-2 ledger, and a correct adapter reads 0 under both. Break: M10 (the new turn expects what the idle reload would give) fails that control. Not repeated for D9: the desktop's refusal is observable in its response (409, `conversation_busy`), and D9's idle reload sends `expected_generation` 1, which a hidden commit would turn into a conflict, so both are already judged on their own evidence.

**2. The runtime's conversation ID is observed nowhere.** Accepted as a limit and a blueprint gap, as disposed: `DESIGN.md` states that the instrument cannot catch a `/new` that updates the binding but not the ID the runtime passes to `Session.Run` (`cmd/tui/chat/chat.go:1158`), and records gap 6 for OQ-4. Source check made for this record: today's `/new` keeps the same ID (`resetChat`, `chat.go:997-1022`); the ID reaches agent events and the compactor's request struct (`agent/compactor.go:57`) but no request the daemon receives. The empty-chat hint is a function of the ID (`chat.go:983-990`) and was considered as an observable and rejected: cosmetic, colliding by design, and it would tie the gate to interface text.

**3. A request with the wrong HTTP method could score correct.** Built: the fake answers each known path only with the methods the real daemon's route table registers (`server/routes.go:1859-1891`; the real engine sets `HandleMethodNotAllowed` at `:1852`), 405 otherwise (`oq3RouteMethods`, `serve`). Every method and path the unchanged clients used in the revision-2 baseline is in that table (GET for `/api/experimental/model-recommendations`, `/api/ps`, `/api/status`, `/api/tags`, `/api/version`; HEAD `/`; POST for `/api/chat`, `/api/generate`, `/api/me`, `/api/show`). Captures are grouped by method; a model request to `/api/chat` with another method is an incorrect delivery (`wrong-method`) and is never frozen as a golden; a preload with another method is an auxiliary failure; any other request refused for its method is an auxiliary failure (`method-check`). Controls: a metadata request with the wrong method; a desktop turn's own request replayed as PUT (405, delivery bad, `wrong-method`) and as POST (200, correct). Breaks: M04 (the fake serves any method) and M05 (the scorer ignores the method) each fail a control.

**4. The leak scan read raw bytes and ignored headers and query strings.** Built: captures record the query string and headers; credential-shaped header values are stored redacted, and the instruction scan reads them unredacted when the request arrives (`record`, `oq3CredentialHeader`). The scan decodes: every JSON string and object key, JSON found inside a string (to four levels), a non-JSON body as text, the path, and the query's keys and values (`oq3BodyLeaks`, `oq3EnvelopeLeaks`). It covers every capture's path, query and headers, and the body of every capture not already compared with an expectation or a golden (scored deliveries, summarisers and preloads are compared on decoded values already). The compaction check reads the next request decoded as well. Controls: the sentinel escaped as `\u0053`, the carrier header escaped as `\u0055`, a sentinel as an object key, a sentinel escaped inside JSON inside a string, a sentinel in a header, the carrier text in a query string; each is reported, and the control asserts that the escaped ones carry no marker in their raw bytes, which the round-2 scan read. A clean metadata request reports nothing. Breaks: M01 (raw bytes again), M02 (no header scan), M03 (no query scan) each fail a control. Limit, stated in `DESIGN.md`: JSON and percent-encoding are decoded; base64 and other encodings are not.

**5. Daemon completion plus 600 ms of quiet did not prove the terminal run had ended.** Built: a terminal turn ends only when the chat proves it is idle (`oq3Terminal.idle`, `oq3Run.mustIdle`). With an empty input a single ctrl+d only arms quitting and sets a status (`chat.go` `updateCtrlD`, `armQuit`) that the chat draws only when no turn, compaction, preload or approval prompt is active (`render.go` `renderActionStatusLines`, `activityLine`, `notificationLine`); a run still in progress overwrites that status when it completes (`chatRunDoneMsg`), so the text cannot appear before the chat is idle. Each probe clears the input first (ctrl+d arms only on an empty input) and ends with ctrl+u, which disarms the quit (`disarmQuit`), so two ctrl+d are never sent without a disarm between them; an open approval prompt ignores both keys (`approval.go` `updateApprovalPrompt`). It replaces the quiet screen after every terminal turn, slash command, start and model switch. Every other wait in the model-picker and launcher branches is now checked (`mustQuiet`, a timeout is a harness failure). Each typed line now starts with ctrl+u (`typeLine`), which clears the chat's input, so a command the chat kept as input while busy (`input.go:100`) cannot prefix a later line. Controls on the real terminal: the probe reads an idle chat as idle; it does not read as idle an open approval prompt after the daemon has fully answered every request it was sent, where the round-2 rule (every response written, then 600 ms of quiet) holds; it does not read a held turn as idle; a command typed while busy does not reach the next turn's text. A runner-level control leaves a turn waiting at an approval nobody gives: the run is invalid at that turn. Breaks: M06 (the probe always reads idle) and M07 (the runner trusts the quiet screen again: the turn is recorded as done and the run fails only later, at `/bye`) each fail a control. M11 (the probe's first ctrl+u removed) and M12 (`typeLine`'s ctrl+u removed) survive, as predicted: each is covered by the other layer (the probe's closing ctrl+u clears the input before its next attempt, and the probe clears the input before the next typed line).

> **Correction (round 3, finding 1; written 27 September 2026).** The statement above that the chat draws the probe's status "only when no turn, compaction, preload or approval prompt is active" is **false for a preload**: while a model preloads the chat draws no activity line (`render.go:1449`) and still draws notifications, so the probe can read idle mid-preload. The falsifier stated under "Technical decisions" below fired on exactly that state. Revision 4 adds a daemon-side preload barrier before the idle proof; see `../oq3-repair-r3/REPAIR.md` and `../oq3-instrument-review-r3/DISPOSITIONS_CODEX.md`.

**6. T10 rejected a permitted refusal at start-up.** Built: against a daemon without `chat.admission.v1`, `terminal-start` accepts a session that preloads and goes idle (the unchanged candidate does), or that refuses at start-up, exiting or staying open (`terminalStartWithoutCapability`). A refusal is recognised only by its report, the daemon's version on screen, matched with white space removed so a wrapped line still matches (A12 and §8: `context_unavailable` naming the daemon's version); a session that ends at start-up without it is a harness failure. After a refusal at start-up the no-dispatch turn records that no request was sent, and the stop step records the session as already ended. A report printed just before exiting is allowed to finish exiting before the session is judged. Controls: a stand-in adapter that reads the daemon's version, reports and exits (held; its turn scored as refused as required; the run valid) and one that exits silently (harness failure). Breaks: M08 (the capability-less path removed) and M09 (an exit without the report accepted) each fail a control.

## Technical decisions (KANON 25), and how they were checked

These were decided from the source, not put to an outside check before deciding, which falls short of KANON 25.3's order for tier-2 choices; the round-3 packet puts each choice and the alternatives it rejected to a different substrate, which may overturn it. The deliberate-break matrix below is the check that runs.

- **The idle proof is the quit prompt.** Rejected: a slash command's output (the chat runs known slash commands even while a turn runs, `input.go:100`, so their output does not wait for idle); the spinner or status line (suppressed by design during the delay after a reply, `render.go:1463`); a plain-text probe (at idle it would start a turn and send a request); Esc and ctrl+c (both cancel a running turn: `chat.go:702-722`, `updateCtrlC`, and `:749-756`, `updateEsc`). Strongest objection: it depends on interface text; a change to the quit prompt or the status line makes runs invalid, never a wrong number. Falsifier: any state in which a turn, compaction, preload or approval is active and the probe reads idle; the controls exercise an approval prompt and a held turn.
- **A start-up refusal is recognised by the daemon's version on screen.** Rejected: accepting any exit (an unrelated crash would read as a correct refusal and pass T10 without evidence); requiring the literal code (the blueprint requires the report to name the daemon's version, §8, not to print the code). Strongest objection: an adapter that reports only to a log would be a harness failure, but §5 requires a missing capability to be shown to the operator. Falsifier: a correct adapter whose on-screen report omits the version.
- **The leak scan decodes JSON recursively but not base64.** JSON inside a string is the same mechanism as the finding and occurs in practice; base64 is a different channel, stated as a limit.
- **Wrong methods.** On `/api/chat` the request is the delivery attempt and is scored against its expectation, bad; it never becomes a golden, so a baseline could not freeze one. Elsewhere a 405 is an auxiliary failure, not a delivery.
- **Only T8 gains a turn**; D9's evidence is argued under finding 1.
- **gofmt as its own commit**, whitespace only, so it adds nothing to review but a mechanical check.
